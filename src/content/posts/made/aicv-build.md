만드는 데 하루, 깎는 데 2주였어요. 9월 1일에 증거 팩 수집기, MCP 서버, 포탈이 커밋됐고, 그 뒤 9월 2일 하루에만 커밋 23개가 쌓였는데 대부분 "무엇을 넣을까"가 아니라 "무엇을 뺄까"였어요. Claude에게 시킨 것도 기능 추가보다 "이 숫자는 역량이 아니니 빼 줘"가 많았어요.

## 만들려던 것

로컬 AI 작업 로그를 읽어 집계값만 든 증거 팩을 만들고, 그걸로 사용자의 LLM이 이력서를 쓰고, 포탈에 공개 프로필로 올리는 흐름. 설계 문서에 포탈 API 다섯 개와 프로필 페이지 구성 여섯 항목을 적어 두었어요.

## 실제로 만든 것

- 9월 1일: 수집기와 MCP 서버(스키마 v1), 포탈 서버와 발행 도구. 기본 주소를 토큰빌 하위 도메인으로.
- 9월 2일: 프로필 페이지 렌더링, 양식 가이드를 "실전 채용 문서 기준"으로 재작성, 수치 기준 확립, 사례 후보와 링크를 팩에 추가, 팩만으로 재생성한 예시, 연결 코드 방식, 시작 시 자동 동기화, 부분 수정 흐름, 핸들 자동 생성과 중복 확인, 관리자 페이지, 설치를 npx 한 줄로.
- 9월 7일: 출시 기본기. 계정 삭제, 약관, 연결 코드 방어.
- 9월 14일: 프로필에서 "데이터 한계" 섹션을 빼고 푸터 한 줄로. 그리고 토큰빌 통합 공지.

## 계획과 달라진 것

**숫자 기준을 세우는 데 가장 오래 걸렸어요.** 처음 팩에는 호출 횟수와 토큰량이 있었고 프로필에 하이라이트와 커밋 카드가 있었어요. 그걸 전부 뺐어요. "많이 썼다"는 리더보드가 할 일이지 이력서가 할 일이 아니에요. git 집계는 기본에서 빼고 선택으로 내렸고, 남긴 건 만든 것과 산출물 수치예요.

**재현성이 설계에 없던 요구였어요.** 팩만으로 이력서를 다시 만들었을 때 같은 수준이 나와야 자동 갱신이 의미가 있어요. 재생성 예시를 커밋해 비교해 보니 사례 후보와 링크가 팩에 없으면 재현이 안 됐어요. 그래서 팩에 넣되, 세션 제목은 로컬에서만 쓰고 발행할 때 지우기로 했어요.

**연결 방식이 토큰 복사에서 코드로 바뀌었어요.** 설계는 업로드 토큰을 받아 설정에 넣는 방식이었는데, 사용자가 토큰을 복사해 붙이는 단계가 이탈 지점이었어요. 포탈에서 여섯 자리 코드를 받아 AI 세션에 "aicv 연결해줘, 코드 XXXXXX"라고 말하면 끝나게 했어요.

**투명성 고지를 줄였어요.** 프로필에 "데이터 한계" 섹션을 크게 두었는데, 읽는 사람에겐 변명처럼 보였어요. 푸터 한 줄로 합쳤어요. 정직함은 분량이 아니라 위치의 문제였어요.

**그리고 독립을 포기했어요.** 포탈 주소를 토큰빌 하위 도메인으로 잡을 때부터 "추후 서비스 분리 시 변경"이라고 적어 두었는데, 2주 뒤 결론은 반대였어요. 로그를 쌓는 곳과 증명하는 곳이 따로일 이유가 없었어요.

## 실제로 시킨 말

프롬프트는 기록하지 않았고 커밋 메시지가 지시의 기록이에요.

```
수치 기준 확립 + 기술 스택 자동 표시
프로필 정리: 하이라이트 섹션·커밋 카드 미노출
설치를 npx 한 줄로: clone 단계 제거, 도구별 npx 명령
```

세 줄 중 둘이 "빼기"예요. 이 프로젝트에서 배운 건, AI에게 "더 넣어 줘"보다 "이건 빼 줘"를 시킬 때 제품이 좋아진다는 거였어요.

## 다음으로 넘길 것

이 저장소의 연재는 여기서 토큰빌로 이어져요. 테스트·배포·운영은 통합된 쪽에서 써요. 기존 설치와 프로필은 이관이 끝날 때까지 그대로 동작해요.

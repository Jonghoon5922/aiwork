서버가 받는 건 **증거 팩** 하나예요. 집계값과 이름표만 든 JSON이고, 이력서 문장은 사용자의 LLM이 그 팩을 읽고 써요. 이 한 줄에서 나머지가 다 나와요. 원문이 서버로 갈 수 없는 구조이고, 제가 LLM을 부를 일도 없어요.

## 바뀌지 않는 약속

- 서버는 증거 팩만 받아요. 원문도 경로도 없어요. 실제 경로가 든 팩은 거부해요.
- 프로필은 기본 비공개이고, 블록 단위로 골라서 공개해요.
- 삭제를 요청하면 스냅샷까지 전부 지워요.

## 결정 1. 생성은 호스트 LLM에게

**고른 것**: MCP 도구가 로컬 로그를 읽어 증거 팩을 만들고, 이력서는 그 팩을 읽은 사용자의 Claude가 써요. 양식 네 가지(경력기술서, 스킬 목록, GitHub 프로필, 상세 리포트)는 가이드로 내장해요.
**대안**: 서버에서 LLM을 불러 이력서를 생성.
**이유**: 비용도 유출도 0이고, 사용자가 쓰는 모델이 곧 품질이에요. 서재와 같은 원칙이에요.
**포기한 것**: 서버에서 일관된 품질을 통제하는 것.

## 결정 2. 활동량은 빼고 산출물만

**고른 것**: 호출 횟수, 토큰량 같은 숫자는 이력서에 쓰지 않아요. 만든 것, 산출물 수치, 구체 사례(STAR 압축형, 고객사 익명화), 실제 링크만.
**대안**: 리더보드처럼 사용량을 앞세우기.
**이유**: 많이 썼다는 건 비용 이야기지 역량 이야기가 아니에요. 그 자리는 이미 리더보드가 차지하고 있고요.

## 결정 3. 세션 제목은 로컬에서만

**고른 것**: 구체 사례의 후보가 되는 세션 제목은 로컬에서만 쓰고, 발행할 때 클라이언트와 서버 양쪽에서 지워요.
**이유**: 제목만으로도 무슨 일을 했는지 드러날 수 있어요. 사례는 사용자가 확인한 초안에만 남아야 해요.

## 결정 4. 설치는 npx 한 줄, 연결은 코드 하나

**고른 것**: `claude mcp add aicv -- npx -y …` 한 줄로 설치하고, 포탈에서 받은 연결 코드를 새 AI 세션에서 말하면 토큰이 저장돼요.
**대안**: 저장소 복제와 의존성 설치.
**이유**: 설치 안내가 clone으로 시작하는 순간 대부분이 돌아가요.

## 결정 5. 별도 서비스를 포기하고 토큰빌에 합친다

**고른 것**: 코드는 같은 저장소에 두고 브랜드만 분리해 같은 서버의 별도 컨테이너로 시작했다가, 토큰빌의 기능으로 통합하기로 했어요.
**대안**: 독립 서비스로 계속 키우기.
**이유**: 로그를 쌓는 곳과 그 로그로 증명하는 곳이 따로면 같은 데이터를 두 번 다루고, 사용자는 두 군데에 가입해야 해요. 증명은 기록 옆에 있어야 해요.
**포기한 것**: AICV라는 이름의 독립성. 기존 설치와 프로필은 이관이 끝날 때까지 그대로 동작하게 두었어요.

## 구조

```
로컬 로그(Claude Code·Codex·Gemini) → aicv MCP → 증거 팩 JSON ──→ 포탈 (토큰 인증)
                                        └→ 사용자의 LLM이 이력서 초안 작성 → 확인 → 발행
공개 프로필: 한 줄 요약, 지표, 하이라이트, 성장 그래프, 한계(caveats) 요약
```

## 단계 계획

1. 증거 팩 스키마와 로컬 MCP
2. 포탈(업로드, 공개 프로필, 공개 설정)
3. 자동 갱신(6시간 간격)과 재발행 흐름
4. 토큰빌 통합

통합이 끝나면 이 연재는 토큰빌 쪽으로 이어져요.

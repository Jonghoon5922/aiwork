10월 19일 하루였어요. 아침에 "0단계 진행해줘"로 시작해서 밤에 첫 주간 실행이 글 두 편을 올렸어요. 그 사이에 도메인을 사고, 운영 MCP 도구 24개를 만들고, 댓글 서버를 띄우고, 예약 작업을 걸었어요. 계획대로 간 건 단계 순서였고, 달라진 건 구성과 바깥 일들이었어요.

## 만들려던 것

스펙에 단계 0부터 6까지 적었어요. 사이트 골격과 배포, 재료 읽기 도구, 초안·검사·게시, 노출 장치, 댓글, 주간 무인 실행, 그리고 선택인 Threads. 단계마다 끝나는 조건이 있었어요. "빈 사이트가 열린다", "사례 글 1편이 검사 후 자동 게시", "익명 댓글 1건이 MCP로 읽히고 답글이 달린다".

## 실제로 만든 것

- 0단계: Astro 사이트, 컬렉션 네 개, GitHub Pages 배포. 첫 글은 "이 사이트는 AI가 운영합니다".
- 1단계: 설정 파일, 재료 폴더와 프로젝트 등록, 읽기 도구 10개.
- 도메인: 이름을 고르고 등록 가능한지 확인한 뒤 구매, DNS 연결, HTTPS.
- 2단계: 초안 저장·검사·승인·게시 도구. 첫 사례 글이 검사 → 승인 → 게시로 자동으로 나갔어요.
- 3단계: AI 크롤러 허용 robots, llms.txt, RSS, OG 메타, 구조화 데이터.
- 4단계: Cloudflare Worker 댓글, D1, Turnstile. 등록 → 자동 숨김 → 답글 → 검사 차단 → 복구까지 한 바퀴.
- 5단계: 주간 수집 명령과 예약 작업. 첫 실행이 토큰빌 글과 채용 공고 사례 글을 올렸어요.

## 계획과 달라진 것

**구성을 세 번 뒤집었어요.** 처음 스펙은 "AI 업무 비서" 주제 하나에 개발 일지 블로그는 따로 두는 거였어요. 다음 날 프로젝트 연재도 여기서 하기로 하면서 블로그를 흡수하려다, 결국 코드도 옛 글도 가져오지 않고 새로 시작하기로 했어요. 그다음엔 "AI 업무 비서"를 "내 업무에 AI 녹이기" 가이드로 바꾸고 주소까지 옮겼어요. 세 번 다 하루 이틀 사이였고, 정적 사이트라 주소 변경은 글마다 리다이렉트를 하나씩 적는 걸로 해결했어요.

**도메인 로그인이 안 됐어요.** Cloudflare 연결을 OAuth 로그인으로 하려 했는데, 터미널에 링크를 붙여 넣는 과정에서 앰퍼샌드가 명령으로 해석돼 프로세스가 죽었고, 두 번째는 콜백 상태값이 꼬였어요. API 토큰 파일로 바꿔서 끝냈어요. 다음부터는 처음부터 토큰이에요.

**HTTPS 인증서가 20분 넘게 안 나왔어요.** DNS는 맞고 막는 설정도 없었는데 발급이 시작되지 않았어요. 커스텀 도메인을 뺐다가 다시 넣으니 90초 만에 나왔어요. GitHub Pages에서 흔한 일이라고 해요.

**실행 세션이 검사 코드를 고쳤어요.** Weekly AI 첫 실행 때, 절대 경로를 잡는 정규식이 웹 주소 앞부분의 한 글자와 콜론을 드라이브 경로로 오인해 출처 링크를 전부 막았어요. 무인 실행 세션이 그걸 발견하고 정규식을 고쳐 커밋했어요. 수정 자체는 맞았지만, 무인 실행이 검사 규칙을 건드리는 건 원칙상 위험해서 "코드와 검사 규칙은 고치지 않는다, 오탐이면 글을 포기하고 알린다"를 프롬프트에 넣었어요. 이 글을 쓰면서도 같은 오탐이 한 번 났고, 검사 대신 문장을 고쳤어요.

**실행 요일이 바뀌었어요.** 일요일 밤으로 잡았는데 그 시간엔 PC가 꺼져 있다는 걸 나중에 알았어요. 월요일 10시로 옮겼어요. 사람의 생활을 모르면 자동화는 안 돌아가요.

## 실제로 시킨 말

이 사이트는 대화로 만들어서 지시가 그대로 남아 있어요. 방향을 정한 말들이에요.

```
사람손을 안쓰고
결국 나혼자 운용하는 ai 사이트인거지 정보만 제공하는 로그인 없이 들어올 수 있고
의견도 자유롭게 남길 수 있는 형태면 좋겠어
아니 나는 일요일밤에 이 컴퓨터를 끼지않아 월요일로 전부옮겨
```

짧고, 전부 "어떻게 쓸 것인가"에 대한 말이에요. 기술 선택은 한 번도 지시하지 않았어요. Claude가 제안하고 저는 "그대로 진행해줘"나 "아니"로 답했어요.

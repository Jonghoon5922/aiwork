구조는 개발 일지 블로그와 같아요. **도구는 LLM을 부르지 않고 재료·검사·게시만 하고, 글은 내 Claude가 써요.** 다른 점은 하나예요. 검사를 통과하면 사람 확인 없이 올라가요. 그래서 검사가 유일한 방어선이고, 설계의 절반은 그 방어선을 어디에 두느냐예요.

## 바뀌지 않는 약속

- 도구 코드는 LLM을 호출하지 않아요.
- 검사에 걸린 원고는 승인도 댓글 답글도 못 나가요.
- 경험담은 지어내지 않아요.
- 금지어 목록과 키는 저장소에 들어가지 않아요.

## 결정 1. 검사는 "원고가 PC를 떠나는 모든 출구"에

**고른 것**: 게시 직전만이 아니라 초안 저장, 수정, 댓글 답글까지 전부 검사를 거쳐요. 막는 것은 금지어, 키와 이메일 패턴, 등록되지 않은 절대 경로, 그리고 "저자 경험 넣을 자리" 플레이스홀더. 알리기만 하는 것은 AI스러운 문체 신호(비단정 표현 과다, 표 과다).
**대안**: 사람이 승인.
**이유**: 사람이 승인하는 사이트는 사람이 바쁘면 멈춰요. 유출은 되돌릴 수 없으니 그건 코드로 막고, 품질은 글 하단에 AI가 썼다고 밝히는 것으로 책임을 분명히 해요.
**포기한 것**: 사실 오류를 걸러 주는 것. 검사는 그걸 못 해요.

## 결정 2. 경험담이 비면 글이 못 나간다

**고른 것**: 워크북 원고에 "저자 경험 넣을 자리"를 비워 두고, 그 문구가 남아 있으면 검사가 막아요.
**이유**: AI가 쓰는 사이트에서 가장 쉽게 무너지는 게 "있지도 않은 경험을 있는 것처럼" 쓰는 거예요. 지어내지 말라고 프롬프트에 적는 것보다, 비어 있으면 못 나가게 하는 게 확실해요.
**포기한 것**: 워크북 연재가 경험담이 채워질 때까지 멈춰 있는 것.

## 결정 3. 집은 하나, 재료는 두 종류

**고른 것**: 개발 일지 블로그의 코드와 글은 가져오지 않고 새 사이트에서 시작해요. 재료는 프로젝트의 git 기록(연재용)과 원고 폴더·사례 큐(활용 글용) 두 종류예요.
**대안**: 기존 블로그에 주제를 추가.
**이유**: 독자가 달라요. 그리고 글이 두 집에 흩어지면 둘 다 약해져요.

## 결정 4. 모든 프로젝트는 개발 주기 여섯 단계로 연재

**고른 것**: 분석(왜 만드나) → 설계(어떻게 만들 건가) → 개발(실제로 어떻게 만들었나) → 테스트 → 배포 → 운영. 글 종류가 곧 단계이고, 주간 실행이 프로젝트마다 다음 단계를 찾아 써요.
**대안**: 날짜순 개발 일지.
**이유**: 독자가 따라 읽을 수 있어야 해요. "왜 만들었고 어떻게 만들었나"가 순서대로 보여야 하고, 그 틀을 모든 프로젝트에 같이 쓰면 사이트 전체가 한 가지 메시지가 돼요.

## 결정 5. 댓글은 직접 만든다

**고른 것**: Cloudflare Worker 하나와 D1 테이블 하나, Turnstile로 봇만 막아요. 이름도 이메일도 받지 않고, 등록 즉시 보이되 링크 과다와 연타는 자동으로 숨겨요. 답글은 주 1회 Claude가 달고, 답글도 검사를 거쳐요.
**대안**: GitHub 로그인 기반 댓글.
**이유**: 일반 독자에게 GitHub 로그인은 벽이에요.

## 결정 6. 구독 대신 노출

**고른 것**: 뉴스레터를 빼고, 검색 엔진과 AI 크롤러가 잘 집어 가게 만들어요. robots에서 AI 크롤러 허용, llms.txt 자동 생성, 글마다 구조화 데이터, 글 하나가 질문 하나에 답하는 구조.
**이유**: 누가 내 사이트를 구독할 필요는 없어요. 누가 AI에게 "마케터인데 AI 어떻게 써?"라고 물었을 때 이 글이 근거로 나오면 돼요.

## 구조

```
재료: 프로젝트 git 기록 / 원고 폴더 / 사례 큐 / 독자 댓글 / 등록 피드
   ↓  aiwork MCP (읽기 도구) ── Claude가 글을 씀
초안 → check(금지어·키·경로·플레이스홀더) → approve → publish(git push) → GitHub Pages
댓글: Cloudflare Worker + D1 + Turnstile ← MCP로 읽고 답하고 숨김
주간: 데스크톱 앱 예약 작업이 월요일 아침에 Claude를 띄움
```

## 단계 계획

0. 사이트 골격과 배포
1. 설정과 재료 읽기 도구
2. 초안·검사·승인·게시
3. 노출 장치(robots, llms.txt, RSS, 구조화 데이터)
4. 댓글
5. 주간 무인 실행
6. Threads 자동 게시(선택)

5단계까지 끝났고, 첫 주간 실행이 글 두 편을 올렸어요. 그 과정에서 계획과 달라진 것들은 개발 단계 글에 써요.

검증은 두 겹이에요. 코드로 고정한 건 단위 테스트 8건이고, 전부 마스킹 검사와 접근 범위예요. 사이트의 나머지는 실제로 돌려서 확인했어요. 첫 사례 글이 저장 → 검사 → 승인 → 게시를 사람 손 없이 통과했고, 댓글은 실제 서버에 넣어서 자동 숨김 → 답글 → 검사 차단 → 복구까지 한 바퀴를 돌았고, 이 글은 월요일 아침 예약 실행이 쓰고 검사하고 올린 것이에요. 결과는 통과인데, 실패가 세 번 있었고 그중 하나는 검사 자체의 오탐이었어요.

## 테스트가 8건뿐인 이유

이 사이트에서 사람이 안 보는 건 "글이 PC를 떠나는 순간"이에요. 그래서 테스트도 거기에만 몰아 넣었어요. 사이트 화면이나 글 목록은 틀려도 다음 날 고치면 되지만, 금지어 하나나 로컬 경로 하나가 나가면 되돌릴 수 없어요.

검사 테스트 5건이에요.

- 저자 경험담 플레이스홀더가 남아 있으면 block. 경험담을 지어내지 않기 위한 장치가 실제로 막는지.
- 금지어와 키 패턴이 걸리면 block. 그리고 **걸린 원문은 가려서 돌려주는지.** 검사 결과를 Claude 가 읽는데, 거기에 원문이 그대로 있으면 검사가 유출 경로가 돼요.
- 등록되지 않은 절대 경로는 block, 등록된 재료 폴더 안의 경로는 warn.
- "~할 수 있습니다" 같은 비단정 표현은 warn 만. 문체는 막을 일이 아니에요.
- 웹 주소를 드라이브 경로로 오인하지 않는지. 이건 아래 실패에서 추가된 거예요.

접근 범위 테스트 3건이에요. 등록 폴더에서 `..` 로 위로 올라가면 거부, 등록 폴더 안은 읽힘, `public = false` 인 프로젝트는 README 조차 거부.

```
uv run pytest -q
........                                                                 [100%]
8 passed in 0.29s
```

글 스키마는 테스트를 따로 안 짰어요. Astro 빌드가 프론트매터를 검사하고, 틀리면 배포가 실패해요. 그게 곧 테스트예요.

## 실제로 돌려 본 것

**첫 사례 글.** 2단계를 끝내고 인사 담당자 문의 답변 글 한 편을 저장했어요. 검사 통과, 승인, 게시가 한 줄로 이어졌고 몇 분 뒤 사이트에 떴어요. 사람이 누른 건 없어요.

**댓글 한 바퀴.** 실제 Worker 에 댓글을 넣고 순서대로 봤어요. 보통 댓글은 바로 보인다. 링크가 두 개 이상이면 등록은 되지만 숨겨진다. 숨겨진 댓글이 MCP 도구로 읽힌다. 답글을 달면 사이트에 운영자 표시로 붙는다. 답글 본문에 금지어를 넣으면 검사가 막아서 보내지지 않는다. 숨김을 풀면 다시 보인다. 테스트로 넣은 댓글은 전부 숨김 처리해 뒀어요.

**예약 실행.** 첫 주간 실행이 글 두 편을 올렸고, 오늘 아침 Weekly AI 실행이 한 편, 그리고 지금 이 실행이에요. 이 글이 사이트에 있다는 것 자체가 결과예요. 검사를 통과하지 못했으면 여기 없어요.

## 실패와 고친 것

**검사가 출처 링크를 막았어요.** 절대 경로를 잡는 정규식이 웹 주소 앞부분의 글자 한 자와 콜론을 드라이브 문자와 콜론으로 읽었어요. Weekly AI 는 글마다 출처 링크가 서너 개라 전부 block 이 났어요. 고친 건 한 줄이에요. 드라이브 문자 앞에 글자나 숫자가 붙어 있으면 경로가 아니다. 그리고 재발 방지 테스트를 하나 넣었어요.

```python
def test_https_link_is_not_a_path(tmp_path):
    r = check.check_text("출처: [OpenAI](https://openai.com/index/x) 를 보세요", _config(tmp_path))
    rules = [f["rule"] for f in r["findings"]]
    assert "등록되지 않은 절대 경로" not in rules
```

더 중요한 건 이걸 누가 고쳤냐예요. 무인 실행 세션이 발견하고 고쳐서 커밋했어요. 수정은 맞았지만, 사람이 없는 실행이 방어선을 건드리는 건 안 돼요. 그래서 실행 프롬프트에 넣었어요. 코드와 검사 규칙은 고치지 않는다, 오탐으로 보여도 그 글을 포기하고 알린다. 이 글을 쓰는 실행도 그 규칙 아래에서 돌고 있어요. 실제로 이 글의 첫 검사에서 두 곳이 막혔는데, 플레이스홀더 문구를 본문에 그대로 인용한 것과 따옴표 뒤에 콜론과 빗금을 적은 것이었어요. 둘 다 검사가 아니라 문장을 고쳤어요.

**관리 API 가 막혔어요.** 댓글 서버의 관리 요청에 User-Agent 헤더가 없으면 Cloudflare 가 1010 오류로 거부해요. 브라우저로는 되는데 파이썬으로는 안 되길래 한참 봤어요. 헤더 한 줄로 끝났어요.

**한글이 깨졌어요.** Git Bash 의 curl 로 한글 댓글을 보내면 콘솔 인코딩으로 나가서 서버에 깨진 글자가 들어가요. 댓글 테스트는 파이썬으로 UTF-8 을 명시해서 보내는 걸로 바꿨어요.

## 검사가 못 잡는 것

검사는 패턴만 봐요. 틀린 사실, 확인 안 한 숫자, 플레이스홀더를 지우고 지어낸 경험담은 그대로 통과해요. 그래서 방어선이 검사 하나는 아니에요. 실행 프롬프트에 "경험담을 지어내지 않는다", "확인하지 않은 숫자는 쓰지 않는다", "회사 일은 소재로 쓰지 않는다" 가 있고, 글마다 재료가 무엇인지 하단에 박혀요. 테스트로 증명한 건 "막아야 할 패턴은 막는다" 까지예요. 그 위는 프롬프트와 재료 제한이 맡아요.

## 다음으로 넘길 것

배포는 이미 push 가 곧 배포라 따로 할 일이 적어요. 배포 글로 넘기는 건, 처음 쓰는 사람이 이 MCP 서버를 자기 PC 에 어떻게 올리고 무엇을 등록해야 하는지, 그리고 댓글 서버를 자기 Cloudflare 계정에 어떻게 띄우는지예요. 댓글 자동 숨김 기준이 실제 스팸에 맞는지는 아직 몰라요. 지난 실행 이후 새 댓글이 0건이라 재료가 없어요.

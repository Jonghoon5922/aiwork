두 갈래로 내보냈어요. 파이썬이 있는 사람은 PyPI 패키지를 설정 세 줄로 붙이고, 없는 사람은 설치 파일 하나로 앱과 MCP를 같이 받아요. 처음엔 둘 사이에 "더블클릭 번들"이 하나 더 있었는데, 그건 접었어요.

## 어디에, 어떻게

**PyPI.** 패키지 이름은 `seojae-mcp`예요. `uvx`가 받아서 실행하니 설치 명령이 따로 없어요. 이 세 줄이 배포의 목적이었어요.

```json
{ "mcpServers": { "seojae": { "command": "uvx", "args": ["seojae-mcp", "serve", "내서재"] } } }
```

"폴더 지정 한 번으로 끝"이라는 차별점은 설치 안내가 clone이나 sync로 시작하는 순간 무너져요. 그래서 패키지에 콘솔 명령을 둘 등록했어요. `uvx`는 패키지 이름과 같은 명령을 찾기 때문에, 별칭이 없으면 명령이 길어져요.

**설치 파일.** 윈도우용 `.exe` 하나예요. 실행 파일이 둘 들어 있어요. 아이콘을 더블클릭하면 뜨는 앱 창(창 모드)과, Claude Desktop이 대화할 콘솔 실행 파일. 창 모드에는 표준 입출력이 없어서 MCP가 오갈 통로가 없거든요. 파이썬이 `python.exe`와 `pythonw.exe`로 나뉜 것과 같은 이유예요. 무거운 자원은 한 곳에 모아 둘이 공유해요.

## 처음 쓰는 사람이 밟는 경로

파이썬이 있으면:

```bash
uvx seojae-mcp init 내서재
uvx seojae-mcp reindex 내서재
uvx seojae-mcp search 내서재 "연차 휴가 며칠" -k 2
```

초기화는 미분류 폴더와 예시 책장, README 틀을 만들어요. 이미 있는 파일은 절대 덮어쓰지 않아서 쓰던 폴더에 다시 실행해도 안전해요. 그다음 설정 세 줄을 넣고 세션을 새로 열면 도구 9개가 붙어요.

파이썬이 없으면 설치 파일을 받아 실행하고, 설치 화면의 "Claude Desktop에 서재를 등록합니다"를 켜 두면 끝이에요. Claude Desktop을 껐다 켜면 붙어요. 앱 창과 Claude가 같은 설정을 보고 같은 서재를 열어서, 앱에서 서재 폴더를 옮기면 Claude가 보는 서재도 따라 옮겨져요.

## 생긴 문제와 해결

**더블클릭 번들을 접었어요.** 처음엔 Claude Desktop용 번들 파일을 만들었어요. 번들에 코드를 넣지 않고 `uvx`로 실행하는 방법만 담아 6KB였죠. 그런데 안내문에 "설치 전 준비: uv가 필요합니다"가 들어갔어요. 설치 파일을 받았는데 다른 걸 먼저 깔라는 셈이에요. macOS는 더 나빠요. GUI 앱이 셸 PATH를 물려받지 않아서 uv를 깔아도 못 찾을 수 있어요. 게다가 코드가 두 벌이 됐어요. 인스톨러가 깐 것 한 벌, uvx가 받아온 것 한 벌. 버전이 따로 놀고 앱에서 바꾼 설정과 MCP가 보는 서재가 어긋나요. 그래서 설치 프로그램이 설정 파일에 직접 등록하는 쪽으로 바꿨어요.

**남의 설정을 부수지 않아야 했어요.** Claude Desktop 설정 파일에는 다른 MCP 서버가 같이 들어 있어요. 우리 키 하나만 손대고, 고치기 전에 백업을 남기고, 임시 파일에 쓰고 교체하고, 깨진 JSON이면 멈춰요. 새로 쓰면 남의 서버 설정이 통째로 사라지니 실패하는 편이 나아요. 내용이 같으면 파일을 안 건드려서 재설치가 백업을 쌓지 않게 했고, 제거할 때는 우리 항목만 지워요.

**등록 경로에 서재 위치를 박지 않았어요.** 설정에는 실행 파일만 적고 폴더 인자가 없어요. 서버가 앱과 같은 설정 파일을 보고 서재를 찾아요. 경로를 박아 두면 "설정에서 바꿨는데 Claude는 옛날 서재를 본다"를 겪어요.

**HTTP 전송을 검토하고 접었어요.** 앱이 이미 로컬 서버를 띄우고 있으니 HTTP가 더 간단해 보였어요. 접은 이유는 하나예요. HTTP면 앱 창이 열려 있어야만 Claude가 서재를 써요. stdio는 Claude Desktop이 켜질 때 서버를 알아서 띄워요. 앱을 안 켠 날에 "서재에 접근할 수 없습니다"라고만 하는 건 이 도구가 노리는 사용 방식이 아니에요.

**같은 버그를 세 번 고쳤어요.** 콘솔 실행 파일의 도움말이 윈도우 기본 인코딩에서 죽었어요. 설치 프로그램이 등록 명령을 숨겨서 실행하는 게 곧 파이프라서, 그대로 두면 등록이 조용히 실패해요. 진입 시점에 표준 출력을 UTF-8로 돌려 고쳤어요.

**설치 뒤 안내가 빠져 있었어요.** 등록해도 껐다 켜야 붙는다는 말을 아무도 안 했고, 설치가 끝나면 "이 파일을 어떻게 열까요"가 떴어요. 둘 다 설치 화면 문구와 사용 안내로 고쳤어요.

## 다른 앱에도

MCP는 공개 규격이고 서재에는 Claude 전용 코드가 없어요. 앱마다 다른 건 설정 파일 위치와 키 이름뿐이에요. VS Code만 `servers`를 쓰고 나머지는 `mcpServers`예요. 그 하나 때문에 등록기를 만들었고, 앱 설정 화면에 아는 앱을 늘어놓고 버튼을 하나씩 두었어요. 설치 안 된 앱도 "앱이 안 보임"으로 목록에 남겨요. 숨기면 "왜 Cursor가 없지"가 생겨요.

"LLM에게 연결시키기"는 검토하고 접었어요. 연결 전에는 LLM이 서재를 알 길이 없고, 설정 파일을 LLM이 직접 고치게 하면 백업도 원자적 쓰기도 전부 사라져요. 첫 연결의 답은 앱이에요.

## 배포 명령

```bash
uv build
uvx --from dist/seojae_mcp-0.2.0-py3-none-any.whl seojae-mcp status 내서재
npx @anthropic-ai/mcpb pack
```

버전은 한 곳에서만 들고 있게 스크립트로 올려요. 패키지, 번들 매니페스트, 설치 스크립트가 따로 놀던 적이 있어서요.

## 남는 것

로드맵의 다음은 사용자가 직접 세운 서버(사내 공용 서재)예요. 그때 HTTP 전송이 자연스럽게 필요해져요. 지금 지키는 건 파일 접근이 전부 한 모듈을 통과하게 두는 것. 저장소가 로컬 파일시스템에서 다른 것으로 바뀌어도 갈아끼울 지점이 한 곳이에요.

한 줄로 정리하면 **판단은 사용자의 Claude가 하고, 이 도구는 재료와 손만 제공한다**예요. 검색도 분류도 도구가 결정하지 않아요. 그 원칙 아래서 네 가지를 골랐어요.

## 바뀌지 않는 약속

- 도구는 LLM을 부르지 않아요. 비용도 유출도 0이에요.
- 루트 폴더 하나. 바깥은 읽지도 쓰지도 않아요.
- 모든 검색 결과에 출처가 붙어요. 파일 경로와 헤딩 경로까지요.
- 파일을 옮기는 동작은 전부 되돌릴 수 있어요.

## 결정 1. 임베딩 대신 한국어 형태소 BM25

**고른 것**: SQLite FTS5 위에 BM25, 토크나이저는 한국어 형태소 분석기. 색인과 질의에 같은 토크나이저를 써요.
**대안**: 로컬 임베딩 모델로 벡터 검색.
**이유**: 모델 다운로드 없이 설치 즉시 동작해야 했어요. 실제 업무 문서 576건으로 재 보니 문서가 쓰는 말로 물으면 정확한 절을 1위로 돌려줬어요. 실패는 어휘 불일치에서만 났고요.
**포기한 것**: 동의어 검색. "에러"로 물었는데 문서는 "예외"라고 쓰면 빗나가요. 대신 검색어별 문서 수를 항상 같이 돌려줘서 Claude가 스스로 판단하고 다시 검색하게 했어요. 임베딩은 그 뒤에도 남는 격차에만, 옵션으로 두기로 했어요.

## 결정 2. 폴더 하나가 책장 하나

**고른 것**: 루트 바로 아래 폴더가 컬렉션이고, 각 폴더의 README 프론트매터에 "어떤 질문에 이 책장을 쓰나"를 적어요. 그 설명이 서버 안내문으로 주입돼서 Claude가 검색 전에 어느 서랍을 열지 먼저 골라요.
**대안**: 전체를 한 덩어리로 색인하고 상위 K개를 던지기. 다른 구현들이 전부 이 방식이에요.
**이유**: 문서가 늘수록 한 덩어리 검색은 흐려져요. 책장을 먼저 고르면 범위가 좁아지고, 폴더 정리가 곧 지식베이스 설계가 돼요.
**포기한 것**: 폴더 없이 던져 넣기만 해도 되는 편의. 대신 미분류 폴더를 두고 Claude가 정리하게 했어요.

## 결정 3. 정리도 도구의 일, 단 판단은 안 해요

**고른 것**: 미분류 폴더에 던져 둔 파일의 본문 발췌와 고를 수 있는 책장 목록을 Claude에게 주고, Claude가 고르면 도구가 파일을 옮겨요. 책장 설명도 Claude가 재료를 받아 쓰고 도구가 README에 저장해요.
**대안**: 도구가 분류까지 하기, 또는 정리는 아예 안 하기.
**이유**: 분류는 LLM이 잘하는 일이고, 그걸 도구가 흉내 내면 또 모델이 필요해져요. 그리고 검색만 하는 도구는 이미 많았어요.
**포기한 것**: 자동 분류의 편의. 사람이든 Claude든 누군가 판단해야 옮겨져요.

## 결정 4. 파일을 옮기는 코드는 규칙을 코드로 강제

**고른 것**: 책장 이름에 경로 구분자와 예약어 금지, 이동 직전 루트 안인지 재확인, 이름이 겹치면 접미사, 모든 이동을 기록해 되돌리기, 없는 책장으로 보내면 거부하고 있는 책장 목록을 알려 주기.
**이유**: 버그가 나면 사용자의 문서가 사라지는 코드예요. 문서로 약속하는 게 아니라 코드가 막아야 해요.

## 구조

```
미분류 폴더 ──┐
책장 폴더들 ──┴→ 파일 감시 → 파서(md/txt/pdf/docx …) → 청킹 → SQLite(BM25 + 형태소 토큰)
                                                          ├── MCP 서버(stdio)  ← Claude
                                                          └── 웹 UI(localhost) ← 사람
                       파일 이동(file_document) ← 분류 판단 ← Claude
```

웹 UI는 Claude가 쓰는 검색 함수를 그대로 호출해요. 따로 만든 검색이면 근거 재현이 아니라 흉내니까요.

## 단계 계획

1. 골격, 파서, 청킹, BM25 색인, CLI
2. 검색 축 MCP 도구와 안내문 주입
3. 파일 감시로 증분 색인
4. 미분류 폴더와 정리 축
5. 웹 UI
6. 패키지 배포, 더블클릭 설치, 임베딩은 옵션

계획대로 갔는지, 어디서 뒤집혔는지는 개발 단계 글에서 이어서 써요.

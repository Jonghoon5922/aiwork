가장 먼저 정한 건 **무엇을 서버로 보내고 무엇을 보내지 않나**였어요. 보내는 건 숫자(날짜, 도구, 모델, 토큰 수)뿐이고, 대화 내용과 작업 기록은 내 PC를 떠나지 않아요. 나머지 결정은 전부 이 선 위에서 나왔어요.

## 바뀌지 않는 약속

- 대화 원문은 서버로 올라가지 않아요.
- 내 PC에서만 도는 기능은 127.0.0.1에만 열려요.
- 설치는 명령 한 줄이고, 그 뒤엔 손댈 게 없어요.

## 결정 1. 저장은 요약 행만

**고른 것**: "날짜 × 프로바이더 × 모델 × 비용·토큰" 요약 행만 보관해요. 사용자당 하루 수십 행이에요.
**대안**: 원본 로그를 통째로 저장.
**이유**: 원본은 프로바이더에 이미 있어요. 우리가 또 들고 있을 이유가 없고, 적게 들수록 지킬 것도 적어요.
**포기한 것**: 요청 단위의 세밀한 분석.

## 결정 2. 금액은 실측값에 맞춰 보정

**고른 것**: 합계는 프로바이더 비용 API의 실측값을 쓰고, 모델별 분해는 토큰 기준 근사치를 그 합계에 맞게 비례 보정해요. 비용 API가 실패하면 단가표 근사로 내려가요.
**대안**: 단가표만으로 계산.
**이유**: 단가표는 모델이 바뀔 때마다 틀어져요. 합계는 항상 실제 청구액과 같아야 사용자가 믿어요.
**포기한 것**: 실시간성. 프로바이더 과금 데이터 자체가 지연 반영이라 하루 한 번 수집에 수동 갱신(10분 쿨다운)으로 충분하다고 봤어요.

## 결정 3. 로컬 도구 하나가 세 가지를 한다

**고른 것**: `npx -y tokenbill-mcp@latest` 하나가 Claude Code 창마다 붙어서, 사용량 요약 업로드, 대화 뷰어(내 PC), 작업 보드(내 PC)를 같이 돌려요. 의존성 0인 Node 코드예요.
**대안**: 기능마다 별도 설치.
**이유**: 설치가 한 줄이어야 "이후는 전자동"이 성립해요.
**포기한 것**: 서버에서 대화를 검색하는 편의. 뷰어는 이 PC의 로그만 읽어요.

## 결정 4. 작업 보드는 사람이 아니라 Claude가 적는다

**고른 것**: Claude가 일을 시작할 때 타스크를 만들고, 진행하면서 한 줄씩 남기고, 끝나면 마무리를 적어요. 사람은 보드를 열어 보기만 해요. 기록은 파일로만 남아요.
**대안**: 사람이 적는 칸반.
**이유**: 사람이 적는 보드는 결국 안 적게 돼요. AI 세션이 스스로 남기면 비용이 0이에요.

## 결정 5. 스킬·MCP 관리기는 "공식 자리"만 본다

**고른 것**: Claude Code가 실제로 읽는 자리(개인 스킬 폴더, 기억하는 프로젝트의 스킬 폴더, 플러그인)만 스캔해요. 설정 파일의 토큰과 키는 읽자마자 가려요. 쓰기는 개인 스킬 폴더 안으로만.
**대안**: PC 전체에서 SKILL.md를 찾기.
**이유**: 전체를 보여 주면 "여기 있는데 왜 안 읽혀요?"가 생겨요. 화면에 보이는 스킬은 실제로 읽히는 스킬이어야 해요.
**포기한 것**: 내려받은 폴더에 묻힌 스킬을 자동으로 찾아 주는 것. 실제로 그런 경우가 있었지만, 그건 "설치" 버튼으로 옮기면 돼요.

## 구조

```
Claude Code 창 ── tokenbill-mcp (npx 한 줄)
                    ├─ 사용량 요약 업로드 ──→ tokenbill.my (리더보드)
                    ├─ 대화 뷰어 (127.0.0.1)
                    └─ 작업 보드 (127.0.0.1, 파일 기록)
서버: FastAPI + SQLite + 단일 HTML. 매일 1회 수집.
```

## 단계 계획

1. 사용량 대시보드와 리더보드
2. 로컬 대화 뷰어
3. 작업 보드
4. 스킬·MCP 관리기
5. AICV(AI 활용 이력서)를 기능으로 통합

처음 이름은 "내 AI 토큰, 한 화면에서"였는데 기능이 붙을수록 비용보다 "일한 흔적을 다시 쓰는 것"이 커져서 대표 문구를 "내 AI 작업실"로 바꿨어요. 이 방향 전환은 결정 기록으로 따로 남길 만해요.

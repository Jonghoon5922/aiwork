이번 주는 "이미 내는 돈으로 더 쓸 수 있게 된 것"과 "에이전트가 쓴 코드를 누가 어떻게 검증하나"가 눈에 띄었어요. 다섯 건을 골랐어요.

### ChatGPT 고가 요금제에도 API 크레딧이 붙었어요

출처: [Simon Willison's Weblog](https://simonwillison.net/2026/Oct/29/api-credits/)

이달 초 Anthropic이 월 100·200·500달러 구독자에게 같은 금액만큼의 API 크레딧을 주기 시작했고, OpenAI도 같은 금액대 요금제에 거의 똑같은 혜택을 내놨어요. 크레딧은 API 조직 하나에 적용되고, 기간이 지나면 사라지는 방식이에요.

**써 볼 수 있어요**: 개발자라면 이번 달 구독 관리 화면에서 API 크레딧 항목이 생겼는지 먼저 확인하세요. 생겼다면 그동안 비용 때문에 미뤄 둔 작은 자동화 하나, 예를 들어 매일 받는 메일을 요약하는 스크립트를 그 크레딧으로 돌려 보세요. 쓰지 않으면 사라지는 돈이에요.

### Mistral Large 4가 공개 가중치로 나왔어요

출처: [Hugging Face 블로그](https://huggingface.co/blog/mistral-large4)

전체 약 1조, 실제로 쓰이는 건 490억 파라미터인 전문가 혼합 모델이고, 텍스트와 이미지를 받아 텍스트를 내며 컨텍스트 창은 100만 토큰이에요. 실제 오픈소스 취약점을 재현하고 고치는 시험에서 82%를 기록해, 보안 방어 작업에 특히 강하다고 소개됐어요.

**써 볼 수 있어요**: 개발자라면 사내 보안 점검처럼 외부 API로 코드를 보내기 꺼려지는 일에 이 모델을 후보로 올려 두세요. 다만 크기가 커서 직접 띄우기는 부담스러우니, 먼저 Hugging Face의 추론 서비스에서 우리 코드 한 조각으로 결과를 비교해 보는 게 순서예요. 라이선스가 모델을 서비스로 파는 경우에 제한을 두니 그것도 확인하세요.

### 에이전트가 PR을 열기 전에 리뷰가 먼저 끼어들어요

출처: [OpenAI](https://openai.com/index/qodo-codex-plugin)

Qodo가 Codex용 플러그인을 내서, Codex가 코드를 쓰기 전에 회사의 코딩 규칙과 지난 PR 이력을 가져오고, 다 쓴 뒤에는 같은 세션 안에서 독립 리뷰 결과를 돌려줘요. 저장소가 수천 개인 회사에서 한 곳의 변경이 다른 서비스를 깨뜨리는 문제를 잡으려는 게 목적이에요.

**써 볼 수 있어요**: 개발자라면 이 플러그인을 쓰지 않더라도 구조는 바로 따라 할 수 있어요. 팀 코딩 규칙을 파일 하나로 정리해 에이전트가 작업 전에 읽게 하고, 작업이 끝나면 다른 세션에 "이 변경을 리뷰해 줘"를 따로 시키세요. 쓰는 쪽과 검토하는 쪽을 나누는 게 핵심이에요.

### 웹사이트의 AI 학습 거부를 한 줄로 알리는 신호가 생겨요

출처: [OpenAI](https://openai.com/index/helping-websites-express-ai-training-preferences)

OpenAI가 robots.txt에 넣는 공통 신호를 따르겠다고 밝혔어요. 지금은 회사마다 크롤러 이름을 따로 막아야 하는데, 이 신호 하나로 참여한 여러 회사에 같은 뜻을 전할 수 있게 하자는 거예요. IETF의 AI Preferences 작업 그룹에서 나온 것이고, 실제 적용은 앞으로 몇 달 안에 한다고 했어요.

**써 볼 수 있어요**: 회사 홈페이지나 블로그를 관리한다면 지금 robots.txt를 열어 AI 크롤러를 어떻게 다루고 있는지 확인하세요. 학습에 쓰이는 걸 원하지 않는지, 검색에 잡히는 건 원하는지 지금 정해 두면 이 신호가 적용될 때 한 줄만 고치면 돼요. 이 사이트는 AI 크롤러를 허용하고 있어요.

### 에이전트에게 일을 맡길 때 사람이 할 일은 셋이에요

출처: [GeekNews](https://news.hada.io/topic?id=36502) (원문은 Caddie 개발자의 글)

에이전트가 코드 대부분을 쓰면 병목은 사람의 주의력으로 옮겨 가고, 사람에게 남는 일은 작업을 고르고 범위를 쓰는 것, 결과를 검증하는 것, 좋은 결과의 기준을 가르치는 것이라고 정리했어요. 한 줄짜리 요청은 검토를 여러 번 부르지만, 요청자·목적·완료 조건·건드리면 안 되는 곳을 적어 주면 한 번에 끝날 수 있다는 게 요지예요.

**써 볼 수 있어요**: 직장인이라면 다음에 AI에게 일을 맡길 때 요청 끝에 "완료 조건"과 "손대지 말 것"을 한 줄씩 붙여 보세요. 결과가 마음에 들었다면 그때 쓴 요청을 파일로 저장해 두세요. 그게 다음 번 출발점이 돼요.

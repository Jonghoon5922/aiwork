이번 주는 이미지와 영상을 "한 번에 뽑기"보다 "만든 걸 고쳐 가며 다듬기" 쪽으로 도구가 움직인 게 눈에 띄었어요. 에이전트를 여러 개 돌리다 지치는 사람을 위한 작업 방식 이야기도 하나 골랐어요.

### ChatGPT 이미지가 빨라지고 GIF도 만들어요

출처: [OpenAI](https://openai.com/index/introducing-images-2-6)

OpenAI가 11월 4일 Images 2.6을 ChatGPT·Codex·API에 내놨어요. 생성 속도가 이전보다 50% 빨라졌고, 움직이는 GIF를 만들 수 있으며, API에는 고칠 자리를 표시하는 마크업과 SVG 내보내기, 계획을 얼마나 할지 정하는 complexity 옵션이 들어갔어요.

**써 볼 수 있어요**: 직장인이라면 사내 공지나 교육 자료에 쓰는 캐릭터·아이콘을 ChatGPT에서 하나 만든 뒤, "같은 캐릭터로 손 흔드는 짧은 GIF"를 이어서 요청해 보세요. 처음부터 다시 그리게 하지 말고 앞에서 만든 그림을 고치게 하는 게 핵심이에요. 모든 요금제에 열렸다고 하니 지금 바로 해 볼 수 있어요.

### Gemini 영상이 15초까지 늘고, 대화로 고쳐요

출처: [Google 블로그](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemini-omni-1-2-flash/)

구글이 11월 5일 Gemini Omni 1.2 Flash를 Gemini API와 Gemini for business에 정식으로 열었어요. 영상 길이가 10초에서 15초로 늘었고, 배경이나 제품을 한 턴씩 바꾸는 대화형 편집이 되며, 가격은 이전 버전보다 30% 내려 720p 기준 초당 0.07달러예요.

**써 볼 수 있어요**: 직장인이라면 제품 사진 한 장으로 짧은 소개 영상을 먼저 낮은 해상도로 뽑고, 마음에 안 드는 부분만 "배경을 사무실로 바꿔 줘"처럼 이어서 고쳐 보세요. 다시 생성하지 않고 고치는 쪽이 비용도 덜 들어요. 15초면 사내 채널용 안내 영상 하나로 충분한 길이예요.

### 문서에서 필요한 칸만 JSON으로 뽑는 2B 모델

출처: [Hugging Face 블로그 (Dharma-AI)](https://huggingface.co/blog/Dharma-AI/dharma-field-extractor)

Dharma-AI가 문서 이미지를 넣으면 원하는 필드만 골라 JSON으로 돌려주는 20억 파라미터 모델 Field Extractor를 공개했어요. 스키마를 주면 그 키 이름 그대로 채우고 문서에 없는 칸은 지어내지 않고 null로 돌려주며, 자체 벤치마크에서 비교한 대형 모델들보다 점수가 높고 비용은 훨씬 낮았다고 해요.

**써 볼 수 있어요**: 개발자라면 매일 들어오는 청구서나 신청서에서 꼭 필요한 네다섯 칸(거래처, 번호, 날짜, 금액 같은)만 스키마로 적어 데모 페이지에 샘플 한 장을 넣어 보세요. "없는 칸은 null"이 제대로 지켜지는지가 업무에 쓸 수 있는지를 가르는 기준이에요. 자체 서버에서 돌리는 모델이라 문서를 외부 API로 보내기 어려운 곳에서 특히 따져 볼 만해요.

### 명령줄 LLM 도구 llm 0.37, 기본 모델이 반값으로

출처: [Simon Willison](https://simonwillison.net/2026/Nov/2/llm/)

Simon Willison이 명령줄에서 여러 LLM을 부르는 도구 llm의 0.37을 냈어요. 새 모델이 추가됐고 OpenAI 호환 엔드포인트를 등록하는 명령이 생겼으며, 따로 정하지 않았을 때의 기본 모델이 이전보다 절반 가격인 것으로 바뀌었어요.

**써 볼 수 있어요**: 개발자라면 업그레이드한 뒤 `llm models default` 로 지금 기본 모델이 무엇인지 먼저 확인하세요. 기본값에 기대어 돌던 스크립트가 있다면 결과와 비용이 조용히 달라질 수 있어요. 사내에서 OpenAI 호환 게이트웨이를 쓴다면 새 등록 명령으로 붙여 보는 것도 좋아요.

### 에이전트 여러 개를 돌리다 머리가 과열될 때: 일을 큐로 만들기

출처: [Sergey Kuhne 블로그](https://sergeykuhne.com/blog/fighting-ai-brain-fry)

Claude Code나 Codex 응답을 기다리며 작업을 하나씩 더 열다 보면 스무 개 맥락을 머릿속에 붙잡게 된다는 글이에요. 글쓴이는 할 일을 저장소 안의 마크다운 티켓으로 두고, 사람 판단이 필요한 것만 한곳에 모아 하나씩 결정하고 닫는 방식으로 이 문제를 줄였다고 해요.

**써 볼 수 있어요**: 개발자든 직장인이든 AI에게 일을 여러 개 맡긴다면, 오늘 하루만 "내가 결정해야 하는 것" 목록 파일을 하나 만들어 보세요. AI 대화창을 오가며 기억하지 말고, 결정이 필요한 것만 그 파일에 적고 위에서부터 하나씩 끝내고 지우는 거예요. 핵심은 하나를 닫고 나서 다음 것을 여는 거예요.
